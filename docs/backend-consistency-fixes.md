# 验证码、共享授权与组织层级一致性修复

## 行为

- 验证码消费由一条条件 UPDATE 完成。用户作用域为 NULL 的找回密码验证码与指定用户的邮箱验证验证码严格区分；匹配码、邮箱、状态和有效期后才成功。密码或邮箱更新抛出异常时，消费随事务回滚。验证码被重新使用时返回不匹配，过期验证码仍返回过期提示。
- 共享授权由数据库唯一键保证每个接收者/类型/资源只有一条。并发重复分享不覆盖既有授权的 ID 或来源；新增记录仍须通过原有资源权限检查。其他约束错误正常失败。
- 组织层级写入通过事务锁定单一专用数据库行。此锁也覆盖可能整行回写父节点的图片更新；应用多实例间同样互斥。自身、祖先和已有环均不能成为子节点；直接更新组织的父节点也受校验。批次包含缺失或非法节点时不写入部分结果。
- 详情读取在访问到重复父节点时终止并记录警告。历史错误环不会自动删除或改变，避免擅自选择应保留的层级边。

接口和 DTO 结构不变。非法层级请求现在失败，而非成功写入。组织层级写入会串行化；普通详情读取不持有全局锁。

## 迁移

应用启动需要先完成 Flyway V25 和 V26：

1. V25 删除缺少 `user_id`、`resource_type` 或 `resource_id` 的无效授权，对重复三元组保留最低 ID 的记录，并添加三列非空及联合唯一约束。被保留记录的来源不变；不同接收者或不同类型不会合并。迁移涉及真实数据清理，部署前应备份 `user_resource`；此清理不恢复已产生的越权授权，也不自动恢复被删除的重复行。
2. V26 创建并初始化 `group_hierarchy_lock`。新代码依赖此锁行，不能跳过迁移单独部署代码。

没有修改旧迁移的内容。`LATEST_VERSION` 更新至 V26。

部署切换期间应暂停资源分享和层级修改，或协调所有实例停机升级：V25 的清理和加约束不是一个事务，旧实例可能在两步之间写入重复记录；旧实例也不遵守 V26 的层级锁。

## 验证

- Java 17 编译和 `build -x test` 打包通过。默认定向回归 60 个用例通过；MySQL 专用迁移用例在此模式跳过，随后单独在 MySQL 下通过。
- 默认数据库测试使用 H2/MySQL 模式，运行真实 MyBatis Mapper、项目 UUID/Entity 处理器及 Spring 事务代理。
- 在无生产数据挂载的临时 MySQL 8.0 容器中，22 个用例通过：验证码并发和业务失败回滚、授权历史去重与约束、授权并发插入、组织写入防环与跨事务竞争，以及 Flyway 从空数据库执行全部 26 个迁移、校验历史并再次迁移不产生变更。
- 可设置 `ONEPIECE_TEST_MYSQL_PORT`、`ONEPIECE_TEST_MYSQL_PASSWORD`，运行 `VerificationConcurrencyTests`、`SharedResourceConcurrencyTests`、`GroupHierarchyTests` 和 `MySqlMigrationTests`。测试仅连接本机指定端口，以 root 创建并在结束时删除随机命名的 `backend_regression_*` 数据库；只能指定隔离的临时测试实例。未设置端口时，前三个测试使用 H2，完整 MySQL 迁移测试跳过。
- 除本轮自行创建的临时 MySQL 实例外，没有访问外部数据库，没有发送实际邮件，也没有执行生产部署。
